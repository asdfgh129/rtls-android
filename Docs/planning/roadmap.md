# RTLS 实施路线图

- 版本：1.0
- 日期：2026-10-19
- 基线：ADR-001 ~ ADR-008
- 预估：2 人并行约 6~8 周；单人约 9~10 周

本文是 Phase 0 之后的执行计划。Phase 0 的详细任务见 [`phase-0-tasks.md`](./phase-0-tasks.md)。

---

## 1. 阶段总览

| 阶段 | 目标 | 关键产出 | 预计 |
|---|---|---|---|
| Phase 0 | 决策、契约、骨架、风险验证 | ADR、协议、DDL、CI、spike 结论 | 3~5 天 |
| Phase 1 | 单设备端到端 | 注册、WS、上报、入库、地图显示自己 | 1 周 |
| Phase 2 | 双设备互查 | 好友、订阅、推送、在线状态 | 1 周 |
| Phase 3 | 历史轨迹 | 历史 API、抽稀、Polyline、保留策略 | 1 周 |
| Phase 4 | 安全与部署 | WSS、Tunnel、Token 加固、备份/监控 | 1 周 |
| Phase 5 | 稳定性与性能 | 电量、负载、OEM、可观测性 | 1 周 |
| Phase 6 | 发布 | Beta、隐私合规、灰度、回滚 | 0.5~1 周 |

**关键路径**：Phase 0 → 1 → 2 → 3/4（可并行）→ 5 → 6。

## 3. Phase 1：Walking Skeleton（单设备端到端）

**目标**：一台设备完成“注册 → 连接 → 上报 → 入库 → 地图显示自己”。

### 服务端

| 任务 | 内容 | 验收 |
|---|---|---|
| 1.1 认证 | 邀请码注册、JWT、Refresh 轮换 | 未认证连接被拒；过期 Token 401 |
| 1.2 WS 网关 | upgrade 鉴权、心跳、envelope、限流、4KB 上限 | 非法消息被拒 |
| 1.3 位置写入 | `location_update` → `locations` + `device_latest` | 重复 `clientMsgId` 不重复入库 |
| 1.4 最新位置 | `GET /v1/devices/:id/latest` | 返回正确坐标与 `stale` |
| 1.5 契约测试 | 路由级/端到端契约（schema 与契约测试已在 Phase 0 的 P0-04 完成） | 正例/反例通过 |

### Android

| 任务 | 内容 | 验收 |
|---|---|---|
| 1.6 权限 | 前台定位、通知、后台定位引导 | 拒绝不崩溃，可恢复 |
| 1.7 FGS | `LocationForegroundService` + 通知 | 连续定位 30 分钟 |
| 1.8 WS 客户端 | OkHttp、Header JWT、30s ping、退避重连 | 断网 30s 后 10s 内重连 |
| 1.9 离线队列 | Room 队列、批量补传、复用 `clientMsgId` | 补传无重复 |
| 1.10 地图 | 百度 SDK、隐私同意、WGS-84→BD-09、自己 Marker | 位置无偏移 |

### 退出标准

- 真机上报成功，数据库有数据；
- 地图显示自己位置，坐标正确；
- 断网 → 恢复 → 补传 → 无重复；
- 越权/未认证请求被拒；
- CI 全绿。

**不做**：好友、历史 UI、生产部署、TDengine。

## 4. Phase 2：双设备互查

**目标**：A/B 互加好友，B 实时看到 A 的位置。

| 任务 | 内容 | 验收 |
|---|---|---|
| 2.1 好友 | 好友码、申请/同意/拒绝/删除/拉黑 | 状态机完整；不能加自己 |
| 2.2 订阅 | `subscribe/unsubscribe`、权限校验 | 非好友/拉黑/关闭分享被拒 |
| 2.3 推送 | fan-out、ACK、去重、离线状态 | B 在 2s 内看到 A（p95） |
| 2.4 presence | 在线/离线/最后在线 | 断线后显示离线 |
| 2.5 Android UI | 好友列表、详情、Marker 更新、平滑移动 | 双机联调通过 |

**退出标准**

- A/B 互加成功；
- B 订阅 A 后实时更新；
- A 断网后 B 看到“离线/最后在线”；
- 解除好友/拉黑后停止推送；
- 关闭分享后停止推送。

---

## 5. Phase 3：历史轨迹

**目标**：查询好友历史轨迹并在地图上绘制。

| 任务 | 内容 | 验收 |
|---|---|---|
| 3.1 历史 API | `from/to/limit/cursor`、7 天上限、5,000 点 | 7 天/5,000 点 p95 < 1s |
| 3.2 抽稀 | 时间桶/Douglas-Peucker（可选） | 大范围查询不超时 |
| 3.3 保留策略 | 90 天清理、用户删除 | 过期数据被清理 |
| 3.4 Android | 时间选择、Polyline 单例、回放 | 连续查询不新建 Polyline |
| 3.5 坐标 | 历史点 WGS-84→BD-09 | 轨迹与地图对齐 |

**退出标准**

- 历史查询有分页/截断标记；
- 轨迹绘制无 GPU 泄漏；
- 过期数据自动清理；
- 非好友无法查询历史。

---

## 6. Phase 4：安全与部署

**目标**：可公网使用的最小安全部署。

| 任务 | 内容 | 验收 |
|---|---|---|
| 4.1 WSS | Cloudflare Tunnel、Public Hostname | 公网只暴露 443 |
| 4.2 心跳 | 30s ping、90s 超时、重连 | 空闲 10 分钟稳定 |
| 4.3 Token 加固 | Header、Refresh 哈希、吊销、限流 | Query Token 被拒；可吊销 |
| 4.4 百度合规 | `setAgreePrivacy`、AK 占位符 | 未同意不初始化 SDK |
| 4.5 运维 | Docker Compose、迁移、备份、健康检查 | 可一键部署/恢复 |
| 4.6 监控 | 日志、指标、告警 | 关键错误可定位 |

**退出标准**

- 源站无 9099/5432 入站；
- WSS 连接稳定；
- 未授权/越权/重放全部被拒；
- 备份可恢复；
- 有回滚 runbook。

---

## 7. Phase 5：稳定性与性能

**目标**：从“能用”到“可长期运行”。

| 任务 | 内容 | 验收 |
|---|---|---|
| 5.1 电量 | 自适应频率、距离过滤、批量上传 | 1 小时追踪耗电基线 ≤ 8%（实测校准） |
| 5.2 负载 | 1,000 连接、200 msg/s | 推送 p95 < 500ms；队列无积压 |
| 5.3 OEM | 小米/华为/OPPO/vivo 真机 | 后台存活通过 |
| 5.4 E2E | 双机、断网、飞行模式、切换网络 | 全部通过 |
| 5.5 可观测性 | 连接数、消息速率、DB 延迟、错误率 | 看板 + 告警 |

**退出标准**

- 无频繁重连风暴；
- 无内存/连接泄漏；
- 关键指标有看板；
- 故障可定位到日志/指标。

## 8. Phase 6：发布

| 任务 | 内容 | 验收 |
|---|---|---|
| 6.1 Beta | 内测分发 | 真实用户可用 |
| 6.2 隐私 | 隐私政策、第三方 SDK 清单、权限说明 | 合规审核通过 |
| 6.3 灰度 | 小流量 → 全量 | 可回滚 |
| 6.4 回滚演练 | 镜像/DB 迁移回滚 | 10 分钟内恢复 |

**退出标准**

- 崩溃率 < 0.5%；
- 连接成功率 > 99%；
- 定位成功率 > 95%（视环境）；
- 回滚演练通过。

## 9. 并行与人员建议

### 2 人（推荐）

- **Server**：Phase 0 的 P0-03/04/05/06/08；Phase 1 服务端；Phase 2 订阅/推送；Phase 4 部署。
- **Android**：Phase 0 的 P0-07/09；Phase 1 权限/FGS/WS/地图；Phase 2 UI；Phase 3 轨迹。
- 联调：每天一次，Phase 1 结束前完成真机闭环。

### 单人

- 严格按 Phase 顺序；
- 先服务端后 Android，但 Phase 1 必须尽快真机闭环；
- 历史 UI 与百度兜底可延后到 Phase 3/5；
- 预留 2 周缓冲。

## 11. Definition of Done

每个 Phase 必须满足：

- [ ] ADR/协议/DDL 已更新；
- [ ] 单元 + 集成测试通过；
- [ ] lint/format 通过；
- [ ] 无明文密钥、无 Token 日志；
- [ ] 迁移可回滚；
- [ ] 验收记录（日志/截图/指标）；
- [ ] 文档与实现一致。

## 12. 关键指标（Beta 目标）

| 指标 | 目标 |
|---|---|
| WS 连接成功率 | > 99% |
| 位置推送延迟 p95 | < 2s |
| 历史查询 p95（5,000 点） | < 1s |
| 崩溃率 | < 0.5% |
| 定位成功率 | > 95%（室外） |
| 1 小时追踪耗电 | ≤ 8%（基线设备） |
| 重连恢复时间 | < 10s |

> 指标是目标值，Phase 5 用真实设备校准；不达标时优先修复而不是改指标。

## 13. 主要风险

| 风险 | 阶段 | 应对 |
|---|---|---|
| 无 GMS 设备 | Phase 0/1 | 百度/高德兜底 |
| 坐标偏移 | Phase 0/1 | 官方转换 + 已知点测试 |
| 后台被杀 | Phase 1/5 | FGS + OEM 白名单引导 |
| 电量过高 | Phase 5 | 自适应频率 |
| Cloudflare 断连 | Phase 4 | 30s 心跳 + 重连 |
| 百度合规 | Phase 0/4 | 隐私同意 + SDK 清单 |
| 单机故障 | Phase 4 | 备份 + 恢复演练 |
| 公开仓库 AI 写权限 | Phase 0 | 限制触发者/只读/不启用 |
